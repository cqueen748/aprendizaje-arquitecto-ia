# Hoja de ruta · organización práctica

Esta síntesis recoge la estructura propuesta por Carlos para el repositorio. No sustituye el Strategic Master Plan ni acredita aprobación de cambios curriculares adicionales. Los ejercicios técnicos se integran al programa CRAI; no constituyen una segunda carga horaria independiente.

| Mes | Foco | Evidencia prevista | Estado |
| --- | --- | --- | --- |
| Preparación | Entorno, variables, aritmética y print | Tres scripts existentes | Conservados; no equivalen a semana 1 |
| 1–2 | Python, Git y SQL | Inventario de PDFs progresivo; producto inicial en semana 8 | Pendiente; alcance semanal por concretar |
| 3 | API, PostgreSQL y Docker | API y persistencia documentadas y probadas | Pendiente |
| 4 | RAG local | Prototipo con fuentes y evaluación reproducible | Pendiente |
| 5–6 | MCP y auditoría | Herramientas con permisos, pruebas y trazabilidad | Pendiente |

Los entregables previstos son objetivos, no resultados obtenidos. El calendario completo y la distribución de horas deben enlazarse a su versión canónica cuando se disponga de ella. Esta estructura de seis meses no cancela las fases posteriores del programa anual.

## Forma de trabajo
1. Recuperar lo aprendido sin pistas y fijar un objetivo pequeño.
2. Explicar el comando o concepto: qué hace, para qué sirve y dónde se ejecuta.
3. Carlos predice el resultado antes de ejecutar.
4. Ejecutar y revisar la salida real; diferenciar predicción y evidencia.
5. Carlos modifica un caso y explica su razonamiento.
6. Registrar dificultades, evidencia y próximo paso; revisar el diff antes del commit.
7. Recuperación espaciada orientativa a 1, 7 y 30 días; recordatorios solo si se programan aparte.

No avanzar por calendario si falta evidencia del gate. No publicar datos de clientes ni generar la solución de un ejercicio antes de la respuesta independiente.
